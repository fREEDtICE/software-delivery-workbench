# Q0 隔离试点恢复与撤权

同一套隔离部署复跑三种情况。编译服务接单后丢回执，工作中的 Runtime 被回收，仍有效的任务租约被主动撤销。控制端和重新获权的 Runtime 都找回了原构建，编译端只执行一次。

| 验收项 | 可核对的记录 |
| --- | --- |
| 构建中回收 Runtime | 编译服务已读到并核对源码，在生成产物前停在受控断点。旧 Runtime 被强制停止并删除。控制端重启后，原构建仍为 `running`。新 Runtime 的临时目录为空。 |
| 丢回执后恢复原任务 | 第一次提交在编译端持久登记后断开连接。控制端只保存请求标识、任务号和源码摘要。重启后按请求标识查回原构建。构建中和完成后各重提一次，均返回原构建号。编译端只有一次接单、一次编译和一次产物写入。 |
| 旧租约立即失效 | 原租约先成功用于保存和模型调用。撤权确认后，旧租约对工作区保存和原授权模型的首次请求均返回 `403 lease_revoked`。两次请求时租约均未到期，存储和授权模型接收端的记录增量均为零。 |
| 新 Runtime 重新获权 | 策略服务发放只可读构建的任务租约。替换 Runtime 经工作区用原请求标识读到进行中状态和最终回执。回执关联同一构建，产物的三个用例为 `21、0、200`，Multica 任务完成。 |

通过 [现有试点工作流](https://github.com/fREEDtICE/software-delivery-workbench/actions/workflows/q0-pilot.yml) 复跑。证据包的 `deployment.json` 中，`recovery` 记录回执丢失、回收与重启、两次重提和替换 Runtime 查询，`revocation` 记录撤权和入口实测，`receiver_events` 保留接收端事件。

试点使用合成源码、单个工作任务和短期租约。编译器与 Runtime 在同一 Linux 主机的不同容器和私有网络中。故障断点设在编译服务读件后、生成产物前。撤权覆盖撤销确认后新发出的请求。
